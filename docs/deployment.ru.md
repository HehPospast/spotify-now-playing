# Размещение и обслуживание

[README](../README.ru.md) · [English](deployment.md) · [Конфигурация](configuration.ru.md)

## Публичное размещение

Файл `docker-compose.yml` привязывает приложение к `127.0.0.1:8080`. Настройте перед этим адресом HTTPS reverse proxy и разместите приложение в корне отдельного домена.

Добавьте публичный callback в Spotify Developer Dashboard и укажите тот же адрес в `.env`:

```dotenv
SPOTIFY_REDIRECT_URI=https://music.example.com/auth/callback
```

Пересоздайте контейнер и подключите аккаунт через `https://music.example.com/setup`. При HTTPS callback защищённые OAuth cookie включаются автоматически.

В nginx направьте запросы на `http://127.0.0.1:8080`, используйте HTTP/1.1. Для `/api/v1/spotify/public/stream` задайте `proxy_buffering off` и `proxy_read_timeout 90s`: потоку нужно постоянное соединение. Разрешите iframe для `/widget`; страницы настройки и OAuth запрещают встраивание сами.

Если reverse proxy работает в другом контейнере, адрес `127.0.0.1` указывает на сам контейнер прокси. Соедините сервисы через подходящую Docker-сеть и используйте адрес сервиса приложения для передачи запросов.

Запускайте ровно один Uvicorn worker и одну реплику. Опрос Spotify, подписчики SSE, лимиты попыток входа и кэш текста песен хранятся в памяти процесса.

## Обновление

В каталоге с настроенным `.env` и Compose-файлом выполните:

```sh
git pull
docker compose up --build -d
```

Сохраните прежние `.env` и имя Compose-проекта, чтобы приложение использовало исходный ключ шифрования и том данных. Если исходники получены архивом, обновляйте их с сохранением `.env`.

## Данные и резервные копии

В томе `spotify-data` хранится зашифрованное состояние SQLite, включая Spotify-токены и ID Telegram-сообщения. Контейнер работает от UID/GID 10001. При использовании собственного bind mount дайте этому пользователю право записи.

Делайте резервную копию тома вместе с соответствующим `.env`. Перед копированием базы остановите приложение, чтобы файлы SQLite и её журнала были согласованы. Храните копии в закрытом доступе: `.env` содержит ключ расшифровки.

- `docker compose down` сохраняет том данных.
- `docker compose down -v` удаляет том и его содержимое.
- Замена `ADMIN_KEY` меняет только пароль настройки.
- При потере `TOKEN_ENCRYPTION_KEY` сохранённое состояние нельзя расшифровать.

При потере ключа сначала восстановите исходное значение из резервной копии. Если его нет, создайте новую базу и ключ, затем подключите Spotify заново. В новой базе также не будет старого ID Telegram-сообщения, поэтому публикация начнётся с нового сообщения.

## Журналы и доступность

В команде Uvicorn отключены access logs. На прокси исключите или очистите query string `/auth/callback`, чтобы коды авторизации и state не попадали в журналы. Не включайте HTTP debug logs с рабочими ключами.

```sh
docker compose ps
docker compose logs --tail 50 spotify
curl http://127.0.0.1:8080/healthz
```

Health check проверяет, что приложение отвечает на запросы. Доступность Spotify, Telegram и провайдера текста проверяется отдельно. Ошибки внешних сервисов описаны в [разделе решения проблем](configuration.ru.md#решение-проблем).

## Публичное воспроизведение

Виджет и playback endpoints публичны. Посетителям доступны текущий трек, позиция, пауза, обложка и включённый текст песни. Пароль владельца страницы `/setup` храните в закрытом доступе. Чтобы прекратить показ, отключите Spotify через `/setup` или остановите приложение.
