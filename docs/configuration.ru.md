# Конфигурация

[README](../README.ru.md) · [English](configuration.md) · [Размещение](deployment.ru.md)

Настройки читаются из переменных окружения. Docker Compose загружает их из `.env` в корне репозитория. Образец находится в [.env.example](../.env.example). Файл с настоящими ключами не должен попадать в Git.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SPOTIFY_CLIENT_ID` | Client ID вашего приложения Spotify | Обязательно |
| `SPOTIFY_REDIRECT_URI` | Точный callback из настроек Spotify | `http://127.0.0.1:8080/auth/callback` |
| `ADMIN_KEY` | Пароль владельца, минимум 32 символа | Обязательно |
| `TOKEN_ENCRYPTION_KEY` | Ключ Fernet: 32 случайных байта в URL-safe Base64 | Обязательно |
| `DATABASE_PATH` | Путь к SQLite | `data/state.sqlite3`; в Compose `/data/state.sqlite3` |
| `POLL_INTERVAL_SECONDS` | Интервал опроса Spotify, от 5 до 300 секунд | `10` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота | Пусто |
| `TELEGRAM_CHAT_ID` | Канал или чат Telegram | Пусто |
| `TELEGRAM_LANGUAGE` | Язык сообщений Telegram: `en` или `ru`; не влияет на виджет | `en` |
| `SPICY_LYRICS_SECRET_KEY` | Серверный ключ приложения Spicy Lyrics | Пусто |

Помощник настройки генерирует пароль владельца и ключ шифрования. Существующий `.env` не перезаписывается. `ADMIN_KEY` можно менять отдельно. Замена ключа шифрования не перешифровывает сохранённые данные.

После изменения конфигурации пересоздайте контейнер:

```sh
docker compose up -d --force-recreate
```

## Spotify

Создайте приложение с доступом к Web API в [Developer Dashboard](https://developer.spotify.com/dashboard). Зарегистрируйте точный `SPOTIFY_REDIRECT_URI`, включая протокол, порт и путь `/auth/callback`.

Для локального HTTP используйте `127.0.0.1` или `[::1]`. Для удалённого callback нужен HTTPS. Spotify не принимает `localhost` как адрес перенаправления. Подробнее в [правилах redirect URI](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri).

Используется Authorization Code с PKCE и единственным разрешением `user-read-currently-playing`. Вход начинается на `/setup` и требует пароль владельца. На протяжении всего входа используйте один адрес, чтобы браузер мог передать OAuth cookie при возврате.

В development mode действуют требования к Premium и списку разрешённых аккаунтов. Актуальные ограничения приведены в [Spotify quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes). Для каждой самостоятельной установки рекомендуется собственное приложение Spotify.

Все посетители и Telegram используют один опрос Spotify. Между обновлениями браузер рассчитывает прогресс локально. Лимиты API могут увеличивать задержку; подкасты, реклама и локальные файлы отображаются как отсутствие поддерживаемого трека.

Отключение через `/setup` удаляет локальные токены Spotify и очищает виджет. Для отзыва самого разрешения удалите приложение в [настройках аккаунта](https://www.spotify.com/account/apps/).

## Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Добавьте его администратором канала с правами публикации и редактирования своих сообщений. Для личного чата сначала отправьте боту `/start`.
3. Заполните одновременно `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

```dotenv
TELEGRAM_BOT_TOKEN=your-bot-token
TELEGRAM_CHAT_ID=@your_channel
TELEGRAM_LANGUAGE=en
```

Укажите `TELEGRAM_LANGUAGE=ru` для русского или `TELEGRAM_LANGUAGE=en` для английского (используется по умолчанию, если переменная отсутствует). Настройка меняет только сообщение о паузе/отсутствии воспроизведения и подписи неизвестного исполнителя/названия в Telegram. Названия треков и имена исполнителей из Spotify сохраняются. Неподдерживаемое или пустое значение языка вызывает ошибку конфигурации при запуске. После изменения `.env` выполните `docker compose up -d --force-recreate`. При смене языка существующее сообщение редактируется, если его текст изменился; ID сообщения сохраняется.

Для публичного канала подходит `@username`. Закрытому каналу нужен числовой ID с префиксом `-100`, личному чату нужен его числовой ID. Получить ID после сообщения или публикации можно через [getUpdates](https://core.telegram.org/bots/api#getupdates). Метод недоступен при установленном webhook. Ответы проверяйте локально, токен бота храните в закрытом доступе.

Интеграция создаёт текстовое сообщение методом [sendMessage](https://core.telegram.org/bots/api#sendmessage), затем редактирует его через [editMessageText](https://core.telegram.org/bots/api#editmessagetext). Обработка команд и webhook не требуются.

Редактирование выполняется только при изменении текста сообщения. ID сохраняется, а удалённое сообщение заменяется при следующем изменении воспроизведения. Интервалы повторов Telegram учитываются. При ошибке Spotify последнее сообщение остаётся без изменений до успешной проверки воспроизведения.

Для отключения оставьте обе переменные Telegram пустыми. Если указана только одна, приложение сообщит об ошибке конфигурации.

## Spicy Lyrics

Создайте приложение в [Spicy Lyrics dashboard](https://developers.spicylyrics.org/dashboard/applications) и укажите его секретный ключ в `SPICY_LYRICS_SECRET_KEY`. Ключ остаётся на сервере. Название трека и прогресс работают без этого ключа.

Адаптер поддерживает обычный текст, синхронизацию по строкам и слогам, включая фоновый вокал. В виджете доступна ручная прокрутка с возвратом к текущей строке после бездействия. Ссылки на источник и авторов синхронизации отображаются вместе с текстом.

Кэш текста хранится только в памяти максимум 24 часа. Перед включением изучите [условия сервиса](https://developers.spicylyrics.org/terms), [правила атрибуции](https://developers.spicylyrics.org/docs/attribution) и [уведомления о сторонних компонентах](../THIRD_PARTY_NOTICES.md).

## Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Spotify отклоняет callback | Адрес в Dashboard точно совпадает с `SPOTIFY_REDIRECT_URI`; локально используется `127.0.0.1` |
| Вход сообщает об истёкшем или неверном state | Начните заново на `/setup` в том же браузере; попытка входа действует 10 минут |
| Spotify возвращает `403` | Аккаунт соответствует ограничениям приложения |
| Spotify возвращает `429` | Дождитесь повторной попытки или увеличьте `POLL_INTERVAL_SECONDS` |
| Spotify требует повторного входа | Подключитесь через `/setup`; refresh token мог быть отозван |
| Telegram возвращает `403` | У бота есть доступ к чату и необходимые права в канале |
| Сообщение Telegram не появляется | Заполнены обе переменные, указан правильный чат, в личном чате отправлен `/start` |
| Текст песни недоступен | Указан ключ провайдера и для трека существует текст |
| Состояние не расшифровывается | Восстановите исходный `TOKEN_ENCRYPTION_KEY` из резервной копии |

Кнопка **Check connection** на `/setup` показывает состояние интеграций. `GET /healthz` сообщает о работе приложения и не проверяет внешние сервисы. В журнале контейнера доступны коды ошибок провайдеров без токенов:

```sh
docker compose logs --tail 50 spotify
```
